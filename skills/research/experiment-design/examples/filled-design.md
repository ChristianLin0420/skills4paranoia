# 實驗設計 — 共享世界模型能否在示範資料減半下維持成功率

這是一份填完的範例，用來示範每一欄該有多具體。數據為虛構。

```
狀態      已定案（主指標與 null 定義凍結）
定案日期  2026-09-08
commit    4f2ac91
預算      H100 × 64 × 14 天 = 21,504 GPU-hours
```

## 1. 要回答的是非題

共享世界模型能否在示範資料減半（51k → 25k）的情況下，維持與全量資料相同的 held-out 成功率？

> 可以答否：如果減半後成功率掉超過門檻，答案就是不能。

## 2. 基準與預算匹配

| 組別 | 設定 | 資料量 | 算力 | 參數量 | 超參數搜尋次數 |
|---|---|---|---|---|---|
| 對照 A | 共享世界模型，全量資料 | 51k demos | 200k steps | 1.20B | 12 組 |
| 對照 B | 無世界模型，半量資料 | 25k demos | 200k steps | 1.24B | 12 組 |
| 實驗 | 共享世界模型，半量資料 | 25k demos | 200k steps | 1.20B | 12 組 |

放掉的維度與理由：參數量差 0.04B（3%），因為世界模型與其替代模組的大小無法完全對齊。三組的超參數搜尋各給 12 組隨機取樣，搜尋空間相同。

> 為什麼要兩個對照：只比對照 A 會分不清掉的是「資料減半」還是「沒有世界模型」。

## 3. 主指標與最小可偵測差異

```
主指標        held-out 12 個任務的平均成功率（擾動條件下）
重複單位      seed（訓練 run）。rollout 不是重複單位。
既有 σ        4.1pp（來源：runs/2026-08 同設定 6 個 seed 的標準差）
想偵測的差異  5pp（低於這個幅度不影響 Q4 的資源決策）
需要 seed 數  每組 10 個
實際 seed 數  每組 10 個，事先講定，全部都要報
每 seed rollout 100 / task
實際可偵測    5.1pp
```

聚合方式：每個 seed 先算自己在 12 個任務上的平均 → 在 10 個 seed 的平均之間算 mean 與 std。`n = 10`。

> 這裡的算術：`2.80 × 4.1 × √(2/10) = 5.1pp`。想偵測 5pp 剛好落在能力邊緣，所以 10 個 seed 是下限不是餘裕。
>
> 如果預算只夠 3 個 seed，這一欄要寫「實際可偵測 9.4pp，本實驗偵測不到 9pp 以下的效果」，而不是照跑然後說趨勢正向。

排除 run 的規則（事先定義，三組同一條）：訓練中出現 NaN loss 且無法從最近 checkpoint 復原者排除，並補跑一個新 seed。

## 4. 什麼結果算 null

實驗組與對照 A 的主指標差異**大於 5pp**（即減半明顯掉太多），或 95% 信賴區間的下界低於 −5pp。

> 注意方向：這是一個非劣性問題，不是優越性問題。我們要證明的是「沒有掉太多」，所以 null 是「掉太多」。這一欄如果寫成「實驗組沒有比對照組好就算 null」，整個實驗的邏輯就錯了。

次要指標：長時序子集成功率、單步推論延遲、訓練 wall-clock。**事先聲明它們不能用來翻案** —— 主指標落在 null 時，不能改拿次要指標宣稱成功。

## 5. 停止與決策規則

```
停止條件   200k steps，或 held-in 成功率連續 20k steps 無改善
差異 < 2pp     → 資料減半可行，Q4 把省下的算力投到長時序任務
差異 2–5pp     → 可行但有代價，先補 25k→35k 一組再決定
差異 > 5pp（null）→ 資料減半不可行，Q4 維持全量並重新評估資料取得成本
```

三個下一步不同，所以這個實驗有資訊量。

## 6. 評估協定

```
held-out 層級   物件實例 + 場景（asset id 與 scene id 交集為空，已用 scripts/check_split.py 驗證）
成功判準        物體中心在目標框內、連續 10 幀、夾爪已鬆開、對容器旋轉不變
判準實作位置    envs/criteria.py:success()，訓練中 eval 與最終 eval 共用
eval seed       range(100)，固定，與訓練步數無關，每 episode 重新 seed
rollouts        100 / task × 12 tasks × 10 seeds
擾動            物體擺位 ±3cm、指令改寫 ×3、初始姿態 ×3、光照 ×2
主數字          擾動下的平均成功率；未擾動值一併報告為上界
```

## 7. 執行環境

```
節點指派   三組交錯指派到 8 個節點，每組橫跨全部節點（不做組內集中）
時間跨度   三組同期跑，同一個叢集排程週期內
實際紀錄   runs/2026-09/manifest.csv：run id → 節點 → 起訖時間 → driver 版本
```

## 8. 最可能白跑的原因

1. 半量資料的取樣方式若不是分層抽樣，任務分布會偏掉，量到的是分布偏移不是資料量
2. σ 是從全量資料的 run 估的，半量資料的 σ 可能更大，10 個 seed 會不夠
3. 擾動測試的實作若在三組之間不一致，主數字不可比
