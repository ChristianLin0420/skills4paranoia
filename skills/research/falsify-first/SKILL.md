# falsify-first

**在花大錢驗證一個想法之前，先花小錢找出它會不會錯。**

產出是一個具體的小實驗，加上要改哪幾行 code。

## 四個問題

### 1. 你相信的機制是什麼

一句因果話，不是一個名詞。

- 不行：「世界模型很有用」
- 可以：「共享世界模型讓物理知識跨任務重用，所以新任務只需要學殘差，示範資料需求下降」

寫不出因果句，通常代表還沒有機制假設，只有一個「加了會變好」的期待。那不需要 micro-exp，需要先想清楚。

### 2. 如果這個機制是假的，你會看到什麼不一樣

**這一題是整個 skill 的核心。**

先寫下對立解釋 —— 同樣的觀察還能被什麼解釋？然後問：你的假設和對立解釋，會不會預測**不同的**觀察？

ML 裡最常見的失敗是它們預測同一件事：

> 觀察：加了世界模型，成功率上升。
> 假設 A：世界模型讓物理知識跨任務共享。
> 假設 B：世界模型只是多了參數和一個自監督輔助損失，好處來自容量與正則化。

A 和 B 都預測成功率上升。所以這個實驗**不區分**，跑了也不會讓你更確定。

要區分，就得找一個 A 和 B 預測相反的操作。見第 3 題。

**如果兩個假設在你想得到的所有觀察上都一致，那它們不是兩個假設，是同一個假設的兩種說法。** 這也是有用的結論 —— 代表你該換一個更有內容的機制陳述。

### 3. 最便宜能分辨的實驗是什麼

從「我要證明它有效」翻轉成「我要找出它最可能在哪裡壞掉」。

**探針的價值幾乎全在負結果。** 正結果通常只是「還沒被排除」。所以往最容易失敗的地方打，不是往最可能成功的地方打。這跟直覺相反，而且 agent 會很自然地想幫使用者設計一個容易通過的實驗 —— 不要。

型態與成本見 `reference/probe-types.md`。同時列出兩到三個候選，**依成本排序，先跑最便宜的那個**。零算力的機制探針常常就能先淘汰掉一半的想法。

一個探針要能用，必須通過一題：**如果結果是負的，你會不會真的取消或改掉大實驗？** 先寫下來再跑。答案是「我大概會說小規模不代表大規模」的話，就不要跑 —— 你已經知道自己會無視它了。

### 4. 那個實驗要改哪些 code

產出變更規格，四個欄位。細節與 diff 的規矩見 `reference/intervention.md`。

- 動哪個模組、介入是什麼
- **什麼必須保持完全不變**
- **什麼斷言能證明介入真的生效**
- 這個介入順帶改變了什麼

第三欄最常被漏。**沒有真的發生的 ablation 比不做實驗更糟**，因為你會拿它的結果去做決定。

規格確認之後才問：「要我直接改 code 嗎？」得到明確同意再動手。

## 終止條件

五樣齊了就停，不齊就繼續問：

1. 機制陳述（一句因果話）
2. 對立解釋，以及能區分兩者的觀察
3. 排序過的探針候選，最便宜的那個有明確做法
4. 變更規格，含驗證斷言
5. 負結果會導致什麼行動 —— 寫下來

**這不是 grill-me。** grill-me 問到雙方理解一致為止，開放式；這個問到上面五樣齊全就停，不要繼續發散。

## 輸出

`templates/probe.md` 是空白模板，`examples/worked-example.md` 是填好的範例。從範例改比從空白填快。

跑完之後回到同一份文件，填最下面的結果欄，並對照第 5 項當初寫下的行動。

## 接下來

探針結果支持繼續的話，接 `experiment-prereg` 把大實驗的量測契約鎖死。這裡產生的機制陳述、對立解釋、基準設計會直接餵進去，不用重問。

探針結果是負的，就照第 5 項當初寫下的行動做。**回頭改機制陳述再來一輪，也是完全正常的結果** —— 那正是這個 skill 存在的意義。
